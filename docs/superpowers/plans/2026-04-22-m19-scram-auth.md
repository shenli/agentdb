# M19: SCRAM-SHA-256 auth + tenant-scoped access

Status: in progress (2026-04-22).

Today every AgentDB endpoint is open: `POST /api/tenants/t-42/...`
works from any client on the network, and the Mongo wire
protocol advertises `saslSupportedMechs: []` so clients skip
auth entirely. For a demoable prototype that's fine on
localhost; it's a blocker for running AgentDB anywhere else.
This PR adds real authentication.

## What's in / out

**In:**
- `users` table in meta — `(user_id, tenant_external, iterations,
  salt_b64, stored_key_b64, server_key_b64, created_at_ms)`.
- `agentdb-meta::scram` — SCRAM-SHA-256 crypto primitives:
  password → (salt, StoredKey, ServerKey), server-side
  handshake verification.
- `agentdb-meta::users` — CRUD + "find by username" +
  "verify SCRAM proof".
- Mongo wire: `hello` advertises `SCRAM-SHA-256` when auth is
  enabled; `saslStart` + `saslContinue` implement the server
  side of RFC 5802. Non-auth commands blocked pre-auth when
  `require_auth == true`.
- REST: HTTP Basic auth middleware. When `require_auth == true`,
  every `/api/tenants/:tid/*` request must carry a valid
  `Authorization: Basic <b64(user:pass)>` header, and the auth'd
  user's `tenant_external` must equal `:tid`.
- Admin endpoints: `POST /api/admin/users` (create),
  `GET /api/admin/users` (list), `DELETE /api/admin/users/:id`.
- CLI: `agentdb user add`, `agentdb user list`, `agentdb user
  delete`. `add` reads the password from stdin when not passed
  via `--password` (so it doesn't end up in shell history).
- Env flag `AGENTDB_REQUIRE_AUTH` (default: `false` for backward
  compatibility with existing tests + quickstart).
- Unit tests for SCRAM primitives (RFC 7677 vector round-trip),
  users CRUD, HMAC/PBKDF2 correctness.
- Integration tests: Mongo SASL handshake (client-first →
  server-first → client-final → server-final), HTTP Basic auth
  blocks + allows, tenant ACL rejects cross-tenant access.

**Out of scope (explicitly):**
- **SCRAM-SHA-1.** The MongoDB legacy mechanism. SHA-256 is
  required, SHA-1 is optional per MongoDB 4.0+ and modern
  drivers default to 256. Skipping reduces crypto surface.
- **Password rotation with re-hash.** `user delete` +
  `user add` for now. A dedicated `user rotate` comes with
  the first customer request.
- **Admin-endpoint auth.** The control-plane endpoints
  (`/api/admin/*`) remain open — operators are trusted on
  localhost. Admin-only auth is a separate concern (mTLS or a
  static bearer token) and belongs in its own PR.
- **TLS.** Basic auth over plaintext is obviously worse than
  over HTTPS. The prototype assumes the caller terminates TLS
  at the ingress. Adding TLS termination to the AgentDB
  process is mechanically simple but requires cert
  management we don't want to scope into this PR.
- **Argon2 at-rest hashing.** SCRAM already derives a salted
  StoredKey per RFC 5802; the password never touches disk.
  Argon2 would be an additional hardening layer for the SCRAM
  secrets themselves — not needed for the threat model of an
  open prototype.

## Design

### users table (migration 003)

```sql
CREATE TABLE users (
    user_id          TEXT PRIMARY KEY,
    tenant_external  TEXT NOT NULL,
    iterations       INTEGER NOT NULL,
    salt_b64         TEXT NOT NULL,
    stored_key_b64   TEXT NOT NULL,
    server_key_b64   TEXT NOT NULL,
    created_at_ms    INTEGER NOT NULL
);
CREATE INDEX idx_users_tenant ON users(tenant_external);
```

`user_id` is the SCRAM username. One user maps to exactly one
tenant. Multiple users per tenant is fine (different
applications, different credentials). Stored secrets are
base64 for human-inspectability of `sqlite3 meta.sqlite`.

### SCRAM primitives

Per RFC 5802 §3:

- `SaltedPassword = PBKDF2(password, salt, iter_count, 32)` —
  32 bytes because SHA-256.
- `ClientKey = HMAC(SaltedPassword, "Client Key")` — 32 bytes.
- `ServerKey = HMAC(SaltedPassword, "Server Key")` — 32 bytes.
- `StoredKey = SHA-256(ClientKey)` — what we persist.

At auth time the server never sees `password`, `SaltedPassword`,
or `ClientKey` — only `StoredKey` + `ServerKey` + the client's
proof + the exchanged nonce. Verification is:

```
ClientSignature = HMAC(StoredKey, AuthMessage)
ClientKey_reconstructed = ClientProof XOR ClientSignature
ok = H(ClientKey_reconstructed) == StoredKey   // constant-time compare
ServerSignature = HMAC(ServerKey, AuthMessage)  // sent back
```

`AuthMessage = client-first-bare + "," + server-first + "," +
client-final-without-proof`. Iteration count default 4096 — the
RFC floor. Tune via `AGENTDB_SCRAM_ITERATIONS` at user-create
time for higher-security deployments.

### Per-connection SASL state (wire)

`WireState` gains `Arc<Mutex<HashMap<connection_id,
SaslState>>>`. `SaslState` holds:

- `expected_conversation_id: i32` — stays 1 for the simple
  case.
- `step: SaslStep::AwaitingClientFinal { user_record,
  server_first, combined_nonce }` or
  `SaslStep::Authenticated { user_id, tenant_external }`.

Non-auth commands (`find`, `insert`, `aggregate`, ...) check
`step == Authenticated` when `require_auth == true` and return
`{"ok":0, "code": 18, "errmsg": "Authentication required"}` if
not.

`hello` + `ping` + `saslStart` + `saslContinue` are always
allowed (standard MongoDB behavior — driver has to probe
`hello` to discover mechs before attempting SASL).

### REST Basic auth middleware

Axum `from_fn_with_state` middleware on every `/api/tenants/*`
route:

1. Extract `Authorization: Basic <b64>`; 401 if absent.
2. Decode → `(username, password)`. 401 if malformed.
3. Look up user by `user_id = username`. 401 if missing.
4. Reconstruct SaltedPassword from password+salt+iter, derive
   StoredKey, constant-time-compare against stored one. 401 if
   mismatch.
5. Extract `:tid` from the request path. 403 if
   `user.tenant_external != tid`.
6. Pass through to the handler.

Per-request PBKDF2 is costly (4096 iters ≈ 5–10 ms). For a
prototype that's fine; a real deployment would cache `(user,
computed_stored_key)` or use a session cookie.

### Admin user endpoints

```
POST   /api/admin/users
       Body: { user_id, tenant_external, password, iterations? }
       Returns: 201 with created record (no secrets in body).

GET    /api/admin/users
       Returns: [{ user_id, tenant_external, created_at_ms }]

DELETE /api/admin/users/:user_id
       Returns: 204
```

Under `require_auth == true` these still work without auth —
they're admin-plane, protected by network isolation today.

### CLI

```
agentdb user add <user_id> --tenant <tid> [--password ...]
                                          [--iterations 4096]
agentdb user list
agentdb user delete <user_id>
```

If `--password` is omitted, `user add` reads from stdin (TTY)
with echo disabled via the `rpassword` crate — or a tiny
hand-rolled stdin prompt to avoid a new dep. Pick the
dep-free version; security of prototype CLI prompts isn't
material.

## Test plan

### Unit (agentdb-meta::scram)

- `derive_keys_matches_rfc_vectors` — RFC 7677 test vector:
  user "user", password "pencil", salt "W22ZaJ0SNY7soEsUEjb6gQ==",
  iterations 4096 → StoredKey + ServerKey match published
  values. **This is the single highest-value test in the
  PR** — it proves we implement the standard correctly.
- `verify_rejects_tampered_proof` — small bit-flip in proof
  causes verification failure.
- `constant_time_compare_truly_constant_time` — not a timing
  measurement (flaky in CI), just that the function uses

## Rollout

Auth is **off by default**. `AGENTDB_REQUIRE_AUTH=true` in the
compose example (with a pre-seeded admin user) once the
surface is verified. Existing tests continue to pass because
they don't set the env var. Operators who want auth flip it on
and run `agentdb user add` before exposing the endpoint.
