# M21 Lease Management Implementation Plan (scoped)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Consume the `agentdb-meta::tablets` table (M18) from the runtime. Every tablet (today: every `Box_`) acquires a lease on startup, renews it periodically, and fails writes fast when the lease is lost. This is the first half of the lease + fencing pattern committed to in design §5.5 — the other half (epoch-tagged writes on object storage) lands in a follow-up PR.

## Scope

- `Box_` optionally holds a `LeaseManager`. When absent (no `MetaStore` configured), behavior is unchanged — every existing test continues to work without modification.
- On startup with meta configured: acquire a lease for each box via `tablets::assume_ownership`.
- Background renewal task per box: every `LEASE_RENEW_SECS` (default 10), refresh the lease expiry.
- Pre-write lease check: before `append_event` commits, verify the lease is still live. If not, the write fails fast with a clear error so callers can retry or fail over.
- Metrics: `lease_renewals`, `lease_renewal_failures`, `lease_lost`, `lease_epoch` gauge.
- Integration tests covering acquire / renew / expire-on-meta-loss under `tokio::time::pause`.

## Explicitly NOT in this PR

- **Segment-path fencing.** Design §5.5 calls for `wal/{tablet_id}/epoch={N}/...` so stale-epoch writes are rejected at the storage layer. That's invasive (segment format change) and lands in a follow-up.
- **Scheduler.** Nothing automatically reassigns a tablet when its lease expires; the expired-lease tablet just stops writing. Scheduler is M22.
- **Hot-tablet split.** Still M25.
- **Actual split-brain prevention.** Lease alone prevents a misbehaving writer from renewing indefinitely, but split-brain requires the fencing layer too. M21's PR delivers the ownership coordination; the full end-to-end guarantee needs its follow-up.

Acceptance: a Box_ whose meta-connection is severed stops accepting writes after `lease_expires_at`; metrics + logs surface the transition; existing Box_ behavior without meta is unchanged.

## Steps

- [ ] **A1** New module `crates/agentdb-core/src/lease.rs` with `LeaseManager` struct + `LeaseConfig`.
- [ ] **A2** `Box_` gains `lease: Option<Arc<LeaseManager>>`.
- [ ] **A3** `BoxRegistry::new_with_meta(kv, store, num_boxes, meta, hlc)` constructor.
- [ ] **B1** Startup path: if meta is configured, call `tablets::get_or_create` + `assume_ownership` for each box.
- [ ] **B2** Periodic renewal task spawned per box (handled RAII by a `LeaseRenewalJob`).
- [ ] **C1** Pre-write check in `append_and_fetch_with_actor` — if `lease.is_live()` returns false, fail with a new `Error::LeaseLost` variant.
- [ ] **D1** BoxMetrics counters: `lease_renewals`, `lease_renewal_failures`, `lease_lost`. Gauge: `lease_epoch`.
- [ ] **E1** Unit tests for `LeaseManager` (acquire/renew/expire under virtual time).
- [ ] **E2** Integration test via `BoxRegistry::new_with_meta`: write succeeds; meta connection dropped; lease expires; write fails with `LeaseLost`.
- [ ] **F1** ARCHITECTURE.md section "Lease management (M21)" with the scope+deferred notes.

## Risks

- **Time-sensitive tests.** Mitigation: `tokio::time::pause` + `advance`.
- **Double-connecting to meta from tests that didn't need it.** Mitigation: lease is opt-in via `new_with_meta`; old `new` path is untouched.

## Acceptance criteria

- `cargo test --workspace` passes (existing 324 tests + ~8 new).
- `cargo clippy --workspace --all-targets` clean.
- A Box_ whose meta store is dropped cannot renew its lease and, after the configured lease window, fails write calls with `Error::LeaseLost`.
