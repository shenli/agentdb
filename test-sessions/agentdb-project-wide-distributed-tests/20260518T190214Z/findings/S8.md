# Finding S8: tablet owner failover did not complete

**Scenario:** `S8_raft_quorum_preserves_acknowledged_tablet_writes_under_partition`

**Verdict:** FAIL

**Follow-up status:** RESOLVED by local patch and verified by full remote S8 rerun.

**Classification:** liveness / fault-handling / owner failover

**Commit under test:** remote `li-dev:~/work/agentdb` at `3c291f6f3264352b7fd549be6c60774883a21b44`

## Summary

The real six-node, two-cell cluster smoke reached a healthy pre-failover state, then killed the initial tablet writer `node-a`. The harness expected tablet 1 to move away from `node-a`, but the move was not observed within 45 seconds.

This falsifies the S8 liveness/recovery arm of C17 and weakens confidence in C15/C18 for the evaluation-cluster path. The log does not show an unsafe acknowledged write after quorum loss, so this is not classified as a durability-safety violation from the collected evidence.

## Reproducer

On `li-dev`, sync `~/work/agentdb` to `origin/main`, copy or keep the authored S8 script, then run the command above. The failure occurred in the owner-failover phase after pre-failover consistency, record-index, and changefeed checks had run.

## Suggested next investigation

Inspect the scheduler/owner reconciliation path after process death: node liveness marking, owner lease expiry, tablet reassignment scheduling, and the wait condition used by the smoke harness. The pre-fault scheduler state shows no dead nodes or reassignment activity, so the first useful reduction is a focused six-node run that kills `node-a` immediately after topology convergence and records scheduler ticks plus tablet-owner metadata before and after the kill.

## Follow-up fix

Patch: `bin/agentdb-server/src/main.rs` now calls `reconcile_raft_leader_tablet_ownership(..., allow_owner_transfer = true)` before the scheduler-leader election branch. This lets any node that participates in a local Raft group reconcile control-plane tablet ownership to the Raft leader it observes, instead of requiring the global scheduler leader to also host that tablet group.
